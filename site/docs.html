Native Rust documentation

A direct path to a verifiable dictation session.

Voice Transcriber is a focused desktop desk for Linux, macOS, and Windows. The native binary keeps capture, VAD, review, and export local; only completed segments cross the Groq boundary after consent.

Install a native archive

Open the latest GitHub release and choose the archive matching your target:

TargetArchive
Linux x86_64*-x86_64-unknown-linux-gnu.tar.gz
macOS arm64*-aarch64-apple-darwin.app.zip
Windows x86_64*-x86_64-pc-windows-msvc.zip

Verify the matching SHA-256 sidecar, extract the archive, and run the diagnostics before opening the GUI:

# after downloading the archive and its .sha256 file
shasum -a 256 --check voice-transcriber-*.sha256
./voice-transcriber-*/voice-transcriber --doctor --json
./voice-transcriber-*/voice-transcriber --list-devices --json
./voice-transcriber-*/voice-transcriber

On Windows, use the matching executable from the extracted directory and its PowerShell checksum command. A first launch may require the operating system microphone permission.

Configure

Settings resolve as defaults, then the local config file, then the GROQ_API_KEY environment override. The key is never printed in diagnostics or logs. Cloud onboarding requires an explicit acknowledgement that completed speech leaves the device.

Use Settings to choose a microphone, language, optional English translation, capture mode, copy-on-final, text size, window behavior, export, and opt-in text-only history.

Use

  1. Choose a microphone and confirm it with the local signal meter.
  2. Select Start listening or press Ctrl + Enter.
  3. Speak naturally; local VAD closes a completed segment and the desk keeps request state visible.
  4. Review and edit the ordered transcript, then copy or explicitly export plain text, Markdown, or timestamped text.
  5. Keep history off or opt into bounded text-only retention.

Privacy and data flow

Raw frames remain in a bounded memory queue. VAD and the input meter run locally. In Groq mode, one completed segment is encoded in memory and submitted after consent; the app does not write an audio file or send silence.

Read the plain-language privacy page, field-level data flow, and threat model.

Architecture and release proof

The Rust process separates CPAL capture, local WebRTC VAD, the bounded Groq worker, ordered transcript state, atomic exports, and opt-in history. External work stays off the egui frame loop.

The native release workflow builds three target archives and SHA-256 sidecars. The published v1.2.0 release has verified archive/checksum assets and a downloaded macOS app check; a green build still does not replace Linux/Windows runtime or provider-account evidence. The evidence register records those limits.

Troubleshoot

Provider is not ready

Add a plausible user-managed Groq key in Settings, accept the cloud boundary, and retry. Diagnostics never send audio.

Microphone cannot open

Run --list-devices --json, refresh the picker, confirm the operating system permission, and run --test-microphone --json.

Network or rate-limit failure

Check connectivity and key status, then wait before speaking again. The request queue is deliberately bounded.

Need to report it?

Read the FAQ and use the structured form. Never attach credentials, recordings, transcripts, config files, or full environment dumps.
